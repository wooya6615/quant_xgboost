# 사전등록: XGBoost 분류 -> 회귀 전환 (2026-09)

## 배경

지금까지 전부 이진분류(`label_tb_binary`, 익절 먼저 침=1/아님=0)로 학습해왔음.
방향(이길지/질지)만 맞히는 것보다 **수익률 크기 자체를 직접 예측**하면 더 나은
정보를 뽑아낼 수 있는지 확인. `ret_tb`(triple-barrier 실현수익률, side 보정
반영)는 이미 라벨링 단계에서 계산돼 저장돼 있어 새 라벨 생성 없이 바로 재사용
가능.

## 가설 / 질문

같은 BASE feature(13개)/같은 종목/같은 walk-forward 프레임에서, 라벨을
`label_tb_binary`(분류) 대신 `ret_tb`(회귀)로 바꾸면 fold별 예측력이 개선되는가?
-- "라벨 타입을 바꾼 효과"만 순수하게 격리해서 보는 게 목적이므로, 분류 버전과
다른 조건은 전부 동일하게 고정.

## 고정할 파라미터 (사전등록 -- 결과 보고 바꾸지 않음)

| 파라미터 | 값 |
|---|---|
| feature set | FEATURE_COLS_BASE (13개, 밸류에이션 제외) |
| 타겟(회귀) | `ret_tb` (연속값) |
| 대조군(분류) | `label_tb_binary` (`ret_tb` > 0 -> 1) -- 기존 라벨 그대로 |
| pt_sl | (2, 1) |
| num_days | 20 (064350의 최종 채택값 30이 아니라, 3종목 공통으로 이미 검증됐던 20을 씀 -- 공정 비교를 위해 라벨 타입 외 조건은 전부 고정) |
| 종목 | 064350.KS, 052690.KS, 118990.KQ (3종목 전부 -- 052690/118990은 분류에서 이미 [실패]였지만, "회귀로 바꾸면 그 종목들도 살아나는가" 자체가 흥미로운 질문이라 포함) |
| walk-forward | train_size=300, test_size=60, step=60, embargo=20 |
| seeds | 42, 1, 7, 123, 2024 |
| objective (회귀) | `reg:squarederror`, `reg:pseudohubererror` 둘 다 비교 |
| 평가지표 (회귀) | fold별 Spearman IC (예측값 vs 실현 `ret_tb`의 순위상관) |
| 평가지표 (분류, 대조군) | 기존 AUC / vs_base_rate |

## 통과 기준

- **5-seed 일관성**: fold 평균 IC가 5-seed 중 4개 이상에서 양수, std/mean < 50%
  (기존 AUC 기준과 동일한 엄격도)
- 이 단계에서는 "예측력이 개선되는가"만 확인 -- 백테스트(거래비용 반영 손익)는
  범위 밖. 통과하는 조합이 나오면 다음 단계에서 백테스트.

## 이 실험에서 하지 않는 것

- pt_sl/num_days 자체를 재탐색하지 않음 (이미 확정된 축, 이번엔 라벨 타입만 변수)
- 064350의 최종 채택값(num_days=30)을 쓰지 않음 -- 052690/118990과 조건을 맞추기
  위해 3종목 공통으로 검증됐던 num_days=20 기준으로 통일
- 이상치(2020년 코로나 반등, 2024~2025 조선/방산 테마 등)에 대한 MSE의 취약성은
  알려진 리스크로 인지하고 있음 -- Huber loss 병행이 이를 완화하는지도 같이 확인

## 판정 후 처리

- 회귀가 분류보다 명확히 개선 -> 다음 단계로 회귀 기반 포지션 사이징(예측 수익률
  크기로 베팅 비중 조절) 검토
- 비슷하거나 열위 -> 분류 프레임워크 유지, 회귀는 [실패]로 기록
- 052690/118990이 회귀에서 살아나면 -> 왜 분류에서만 실패했는지 별도 분석
  (방향은 못 맞혀도 크기는 맞히는 경우가 있는지)
