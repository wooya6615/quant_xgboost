# 사전등록: triple-barrier BASE 전용 재검증 (2026-09)

## 배경

`feature_engineering_valuation.py`의 PER=0 버그 수정으로 triple-barrier +
VALUATION-COMBINED 실험 라인 전체(최초 밸류에이션 채택 결정 포함)가 무효 처리됨.
BASE 전용(`build_triple_barrier_dataset()`)은 애초에 밸류에이션 코드 경로를 타지
않으므로 그 버그 자체에는 걸리지 않았지만, 다음 두 가지 이유로 아직 "깨끗한
기준선"으로 볼 수 없음:

1. 지금까지 정식 기록된 성능 수치는 대부분 COMBINED 기준이었고, BASE 단독
   5-seed/국면검증이 최신 라벨링 로직으로 독립적으로 기록된 적이 없음.
2. `train_xgboost_triple_barrier_ablation.py`가 참조하는 파일명(`pt2sl1`)이
   D+1 체결지연 + High/Low 장중터치 반영 이전 버전 -- 라벨축 비교 자체가
   최신 라벨링으로 재현된 적 없음.

## 가설 / 질문

BASE 전용(가격/거래량 파생 13개 feature) + triple-barrier 라벨(`label_tb_binary`,
pt_sl=(2,1), num_days=20, D+1 종가체결 + High/Low 확정판) 조합이, 3개 앵커
종목(현대로템 064350, 한전기술 052690, 모트렉스 118990)에서 개별적으로
5-seed 일관성 + 국면제외 재검증을 통과하는가?

## 고정할 파라미터 (사전등록 -- 결과 보고 바꾸지 않음)

| 파라미터 | 값 |
|---|---|
| feature set | FEATURE_COLS_BASE (13개, 밸류에이션 제외) |
| 라벨 | `label_tb_binary` (label_tb > 0 -> 1) |
| pt_sl | (2, 1) -- 기존 채택값 그대로 유지 |
| num_days | 20 |
| 체결 방식 | D+1 종가체결 + High/Low 장중터치 반영 (최종 확정판) |

| 거래비용 | 0.2% 왕복 (백테스트 단계에서만 적용) |

## 통과 기준 (기존 프로젝트 컨벤션과 동일)

- **5-seed 일관성**: `vs_base_rate` 5/5 양수, AUC std/mean < 50%
- **국면 제외 재검증**: 가장 최근 완결 연도(2025) 절단 후에도 방향 유지
  (Buy & Hold 비교는 "행 삭제"가 아니라 "기간 절단"으로 -- 기존에 한 번
  실수했던 부분이므로 주의)

## 이 재검증에서 하지 않는 것

- pt_sl/num_days 자체를 탐색하지 않음 (그건 이미 PBO 95.6%로 부적합 확정된 축).
  이번엔 순수하게 "밸류에이션 없이 BASE만으로도 이 라벨 정의가 버티는가"만 확인.
- 백테스트(거래비용 반영 손익)까지는 이번 재검증 범위에 포함하지 않음. 5-seed +
  국면검증 통과 여부만 먼저 확정하고, 통과하는 종목에 한해 다음 단계에서 백테스트.

## 판정 후 처리

- 3종목 모두 통과 -> triple-barrier 프레임워크는 유지, "BASE만으로 이미 되던 걸
  밸류에이션이 착시로 개선처럼 보이게 했다"는 가설로 다음 단계(백테스트) 진행.
- 일부만 통과 -> 통과한 종목만 남기고 나머지는 [실패] 태그, 공통 조건(유동성/
  거래대금 등) 분석으로 다음 단계.
- 전부 실패 -> triple-barrier 프레임워크 자체를 [배포 부적합]에 준하는 것으로
  보고, PROJECT_SUMMARY.md "다음 단계 후보" 2번(프레임워크 전환 검토)으로 넘어감.
